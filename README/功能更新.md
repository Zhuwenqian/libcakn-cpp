# 功能更新

> 本文件记录 **cakn-cpp（libckan 独立库工程）** 的功能演进。历史条目整理自 Hello KSP Launcher 的 `README/功能更新.md`（仅收录与 CKAN 库核心逻辑相关的部分），在此基础上继续追加本库自身的更新。

## 2026-08-22：从 Hello KSP Launcher 抽离为独立库

- **背景**：libckan 原为启动器工程的静态/动态库（`src/ckan/`）。为便于单独演进、复用与开源，将其抽离为独立工程 `cakn-cpp`。
- **构成**：仅含 CKAN 核心逻辑（`src/ckan/`）、`thirdparty/miniz`（ZIP 归档，vendor 进仓库）、`tests/test_libckan.cpp`（QtTest 单测）。不含任何启动器 GUI / 实例管理 / UI 代码。
- **构建**：新建独立 `CMakeLists.txt`——`project(cakn-cpp)`；`add_library(libckan SHARED)`（Windows `libckan.dll` / Unix `libckan.so`/`libckan.dylib`），`CKAN_API` 全类导出，产物统一落 `dist/`；`test_libckan` 目标接入 CTest。
- **单测**：`tests/test_libckan.cpp` 与启动器保持一致，`ctest` 全通过即可验证库功能。

## 2026-08-22：libckan 改动态库 + 四层解耦

- **静态库改动态库**：`add_library(libckan SHARED)`，`ckan_export.h` 提供 `CKAN_API` 导出宏：编译库时 `CKAN_BUILD_SHARED + CKAN_BUILDING_LIB`（dllexport），消费者仅 `CKAN_BUILD_SHARED`（dllimport）；GCC 用 `visibility("default")`。库内全部公开类（CKan、CKanConfig、CkanModule、Repository、InstalledModule、InstallResult、ResolutionResult、GameVersion 等）均带 `CKAN_API` 全量导出。
- **门面补全**：`CKan` 补齐 `downloadModules/installFromCache/scanUnmanagedDlls/cancelInstall/releaseInstaller/detectVersionFromDir/safeCacheFileName` 等，封装下载、冲突计算、事务回滚、卸载、取消；对外只暴露最小只读查询接口，内部 `GameInstance` 不再透出。
- **全局可变状态移除**：`Downloader::setProxyUrl` 改实例级；`RepoIndex` 缓存目录/代理/镜像前缀改显式参数；新增 `CKanConfig`（indexCacheDir、proxyUrl、索引/模组镜像前缀、并发数）统一承载配置。
- **构建/测试解耦**：`libckan` PUBLIC include 只暴露 `src/ckan`，`src/` 与 `thirdparty/` 收窄为 PRIVATE；`test_libckan` 回归纯库测试。

## 2026-08-20：安装/卸载/升级事务回滚（原子执行）

- **事务文件管理器**：新增 `TxFileManager`（对应官方 ChinhDo.Transactions.TxFileManager）。所有文件写/删/覆盖操作先备份到事务目录；`commit()` 提交丢弃备份、`rollback()` 完整恢复（还原被覆盖/删除的文件、删除本事务新建文件、还原整目录删除）；未显式提交/回滚即析构自动回滚作安全网。
- **原子安装/卸载**：`ModuleInstaller::installFromCache`/`uninstall` 默认内部自动事务——任一步失败（含取消）整体回滚并还原注册表快照；支持外部传入 `tx`（升级场景由调用方统一提交/回滚）。`GameInstance` 新增 `restoreRegistrySnapshot` 还原内存并同步写回 registry.json。
- **单测**：`TestTransactionRollback` 覆盖——回滚还原一切、批量安装中途失败无残留、用户取消回滚、卸载失败回滚、升级合并事务回滚。

## 2026-08-19：多仓库支持 + 模组下载次数显示

- **多仓库**：预设仓库（KSP-CKAN 备用 GitLab 归档、Sol/RSS-Reborn、MechJeb2-dev CI）或自定义，可删除、调整优先级；`Repository::preset*` 定义（`repository.h/.cpp`）。
- **优先级合并**：仓库按数组顺序即优先级合并，跨仓库同标识符同版本去重、优先高优先级；下载计数按优先级取首个命中；任一仓库失败不中断、回退旧缓存（`RepoIndex::buildManyCached`/`mergeSubIndexes`）。
- **下载次数显示**：解析仓库归档内 `download_counts.json`，经 `CKan::downloadCount` 透传（无数据显 `-`）。
- **修复跨仓库错误回退**：镜像改为前缀，仅对 GitHub 托管仓库按「前缀 + 仓库自身 URL」生成镜像，非 GitHub 不走镜像，杜绝下载到官方仓库内容。

## 2026-08-16：suggests / 级联建议

- **级联建议解析**：`RelationshipResolver::resolve` 新增 `withSuggests`，把安装集（含依赖）各模组的 `suggests` 收集到 `ResolutionResult::suggestedModules`（仅收集、不自动安装），并对建议继续级联展开；已安装/已选中不再作为建议，级联去重防成环。
- **单测**：`TestRelationshipResolver` 覆盖——建议进集合不自动安装、关闭时不收集、级联收集、已安装排除、成环去重、选中后重新解析含其依赖。

## 2026-08-16：build ID → 版本映射

- `GameInstance::detectVersion()` 优先读 `buildID64.txt`/`buildID.txt`（`build id = NNNN`，忽略前导 0，兼容纯数字），经内置静态映射表（数据源自官方 builds-ksp.json，覆盖 0.23.0.395 ~ 1.12.5.3190）换算语义版本；双文件去重取版本最大值。缺失/未命中回退解析 `readme.txt` 版本行，都失败返回无效。实现于 `kBuildMap()`/`buildIdToVersion()`。

## 2026-08-16：下载 SHA256 校验 + 多线程下载 + 修复忽略实际 KSP 版本

- **SHA256 校验**：仓库元数据声明 `download_hash` 的 sha256 时，对下载内容计算比对，不一致判定失败并自动重试镜像，失败结果不写缓存（`ModuleInstaller::downloadOneTask` 的 `zipValidator`）。
- **多线程并行下载**：`downloadModules` 改为 `QtConcurrent::run` + `QThreadPool` 并行下载，保留断点续传、取消与聚合进度（跨线程 `std::atomic<qint64>` 累计字节数）；并发数默认 3、范围 1~8（`ConfigManager::downloadConcurrency`）。
- **修复完全忽略实际 KSP 版本**：新增 `GameVersionRange`（contains/intersects），`CkanModule::isCompatible(ksp)` 基于 `ksp_version`/`_min`/`_max`/`_strict` 构造区间并与实际检测版本比较；`ModsTableModel::setGameVersion` 把实例真实版本传入过滤。

## 2026-08-16：修复模组列表显示旧版本而非最新版本

- **问题**：`CKan::search()` 用 `versions.first()`（字母序最小）作代表版本，如 Kerbal Konstructs 显示 `0.5.1b` 而非官方 `v1.12.2.0`；该旧版 `ksp_version` 为 0.25，按兼容判定被整体隐藏。
- **修复**：`search()` 改用 `RepoIndex::latestFor()` 按版本取最新，列表显示、兼容性过滤、实际安装三者统一。

## 2026-08-16：手动模组文件夹冲突处理 + AD 依赖不重复下载

- **手动模组识别**：`GameInstance::manualGameDataFolders()` 扫描 `GameData` 下未被注册表登记的顶层文件夹（排除 `Squad`/`SquadExpansion`）。
- **AD 依赖不重复下载**：解析依赖时把手动安装（DLL 扫描，AD）模组的标识符加入「已提供」集合，依赖已满足不再下载。
- **两阶段安装 + 冲突检测**：拆分「下载 zip → 读 zip 实际内容推导将写入的 GameData 顶层文件夹并检测冲突 → 从缓存安装」；`ModuleInstaller::actualGameDataFolders` 套用 `as`/`find`/`file` 与嵌套 `install_to` 规则，以 zip 真实内容为准。冲突弹窗三选项：全部覆盖 / 全部删除旧保留新（干净安装）/ 取消。

## 2026-08-14：卸载时级联卸载依赖本模组的模组

- `ModuleInstaller::uninstall` 改为级联卸载，`collectReverseDeps` 递归收集反向依赖链（含虚拟包匹配，`visited` 防环），后序卸载（先依赖者、最后目标）。

## 2026-08-14：修复带 epoch 的模组缓存文件 0 字节问题

- 安装 `version = 1:3.4.0` 这类带 epoch 版本时，缓存文件名 `标识符_1:3.4.0.zip` 中冒号被 NTFS 当作 ADS 分隔符致主文件流 0 字节。新增 `ModuleInstaller::safeCacheFileName()` 把非法字符（`: \ / ? * < > | "`）统一替换为 `_`（`1:3.4.0` → `1_3.4.0`）。

## 2026-08-14：GameData DLL 扫描 + KSP 版本兼容检查

- **手动模组识别（AD）**：`GameInstance::scanUnmanagedDlls()` 扫描 `GameData` 下所有 `.dll`（排除 `Squad`、`SquadExpansion`），以 DLL 文件名第一个 `.` 之前为标识符。
- **KSP 版本兼容检查**：`CkanModule::isCompatible()` 早期固定中版本门槛（`kCompatibleMinMinor = 9`，即 ≥1.9.0 兼容；未声明/非法视为兼容）。

## 2026-08-14：registry.json 补全必填字段（官方 CKAN 兼容）

- `CkanModule::toJsonObject()` 改为与 `fromJsonObject()` 完整往返序列化，补齐 `license`、`author`、`ksp_version`、`download`、`download_hash`、`resources`、依赖关系、安装规则等；`provides` 按 CKAN 原格式输出为标识符列表。新增 `Relationship::toJsonObject()` 与 `ModuleInstallDescriptor::toJsonObject()`。

## 2026-08-14：模组批量安装 / 升级 / 卸载（复选框）

- `CKan::resolveInstallMany`：一次性解析多模块安装集（整体解析，冲突/缺失依赖整体失败）；`CKanManager` 提供 `installBatchAsync / upgradeBatchAsync / uninstallBatchAsync`。

## 2026-08-14：索引获取与模组下载的进度条 / 超时 / 取消

- 模组按批量总字节聚合进度并显示已下载大小与实时速度；索引 tar.gz 未知总量呈不确定态。`setTransferTimeout(30s)` 统一兜底连接 + 空闲超时。下载线程以 `std::atomic_bool` 轮询取消，取消不弹错误框、临时数据不写缓存。`Downloader::downloadProgressed` 新增进度/超时/取消回调；`ModuleInstaller::install` 聚合 `byteProgress`（字节/总量/速度）。

## 2026-08-14：CKAN 下载健壮性 + 仓库索引缓存

- **下载健壮性**：`Downloader::Validator` 内容校验（模组下载校验为 ZIP，非预期内容视为失败并自动重试镜像）；下载前校验缓存有效性，损坏缓存自动删除重下；zip 打开改用内存读取（`mz_zip_reader_init_mem`）规避 Windows ANSI 编码问题。
- **仓库索引缓存**：`RepoIndex::setCacheDir`/`buildCached` 将 CKAN-meta 的 tar.gz 落盘，未过期直接使用本地缓存，过期强制重新下载。

## 2026-08-14：内置 CKAN 模组管理（libckan）

- 用 C++ 重写 CKAN 核心，`CKAN-meta` 仓库与 `registry.json` 格式完全兼容官方版本；保留独立接口（`ckan::CKan` 等类）供接入更多功能。

### 核心逻辑

- `version`：`ModuleVersion` / `GameVersion` 语义化版本比较（含 epoch、build 忽略规则）。
- `ckanmodule`：`CkanModule` JSON 解析/序列化，缺 identifier/version 判无效。
- `relationship`：依赖/推荐/冲突/提供关系描述符及版本约束判定。
- `moduleinstalldescriptor`：安装规则（file/find/find_regexp）解析、文件筛选与路径转换。
- `registry`：registry.json 读写，`installed_modules`/`installed_files`/`sorted_repositories` 完整兼容。
- `relationshipresolver`：BFS 依赖展开，支持 depends/recommends/conflicts/provides，虚拟包索引解析，自动选择满足约束的最高版本。
- `repoindex`：解析 CKAN-meta tar.gz，构建 标识符→多版本 仓库索引。
- `downloader` / `moduleinstaller`：HTTP 下载（镜像/代理）、miniz 解压、安装/卸载与文件归属跟踪。
- `gameinstance` / `ckan`：实例生命周期封装与对外统一入口。

### 单元测试

- `tests/test_libckan.cpp`（QtTest）覆盖版本比较、安装规则、registry、依赖解析、虚拟包、冲突、缺失依赖等全部核心用例，经 `add_test` 接入 CTest。
